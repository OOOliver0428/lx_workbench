# MVP 阶段说明

版本基线：**0.1.0（2026-08-04）**。该版本进入受控试运行部署，后续有效变更统一维护在
[更新日志](../CHANGELOG.md)，版本发布步骤见[发布规范](RELEASING.md)。

## 当前目标

以作战台展示为最终业务界面，跑通“项目与任务管理 → 工作事实记录 → 个人周报提交 →
团队聚合展示”的闭环。展示层只消费服务端按自然周聚合的真实数据，不内置演示数据或
另建手工统计副本。

## 已纳入

- 作战台默认首页：商机追踪清单与关系图、工作管理和五周周期总览。
- 追加式项目周进展、阶段时间线、跨项目任务关联、交付物与成员提交矩阵。
- 基于已正式提交个人周报的团队 AI 汇总；非全员提交时须显式强制并留痕。
- 本地账号、首次改密、会话超时、角色与直属 Leader。
- 按用户显式授权、三个作战台视图独立可见，以及超级管理员永久隐藏。
- 超级管理员配置全部权限；系统管理员只配置团队负责人和成员的业务权限。
- 系统预置头像及全角色个人设置。
- 项目标签、父子层级、负责人、成员、别名、查重、状态流转和合并。
- 项目任务、负责人、协作者、优先级及状态流转。
- 工作记录、半小时工时档位、项目/任务关联、待归集及产出物。
- DeepSeek、GLM、Kimi、MiniMax 的管理员配置、连接测试和密钥加密存储。
- AI 对话与基于当周有效工作记录生成、编辑和提交周报。
- 个人周报按周目维护且仅本人可见；具备团队周报权限的账号可查看自己生成的往期汇总。
- 审计日志、乐观锁、SQLite WAL、Alembic 迁移和一致性备份。

## 本阶段暂缓

- 本地文档上传后由 AI 自动拆分并写入项目、任务和工作记录。
- HTTPS、统一身份认证、多实例高可用和外部对象存储。

## 试运行部署边界

- 仅部署在受控公司内网，使用 IP 与端口访问。
- 前后端固定为单个应用实例；SQLite 数据库必须位于服务器本机磁盘。
- 防火墙只允许试点网段或明确设备访问。
- `.env`、数据库、备份和大模型密钥不进入 Git。
- 正式推广前必须启用 HTTPS，并将安全 Cookie 配置切换为生产值。

## 提交前检查

```powershell
uv run ruff check app tests
uv run pytest

Set-Location frontend
npm run lint
npm test
```

同时确认 Alembic 处于最新版本、示例配置不含真实密钥，且 Git 变更中不存在数据库、日志、
缓存、原始设计素材或旧原型文件。升级权限迁移后，新旧普通账号均不会自动获得业务权限，
需先由超级管理员在“系统设置 → 用户与权限”中完成授权。
