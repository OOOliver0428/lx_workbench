# 自定义头像（v0.5.1 待发布）

已完成手机号绑定的用户可在「个人设置 → 更换头像 → 自定义上传」选图、调整方形裁剪并保存。
JPG、PNG、静态 WebP 原图最多 5 MiB、2000 万像素，输出为 512×512 WebP。
不保存原图、原文件名、EXIF/GPS 等元数据；动图与 SVG 不支持。
用户切换头像后不提供历史回退，旧图 24 小时后进入清理，通常在下一次每小时检查时删除。

## 配置与权限

模块独立于手机号服务，默认关闭。上传资格取自数据库中的已验证绑定状态，不需要读取
手机号加密密钥，也不要求阿里云服务在线。COS 故障、配置不完整或关闭模块不会阻断核心功能；
自定义图片读取失败时，界面回退到姓名首字，用户也可随时切回预设头像。

只在后端 `.env` 或生产 `/etc/solution-workspace/app.env` 注入配置：

```dotenv
MVP_CUSTOM_AVATAR_ENABLED=false
MVP_AVATAR_COS_SECRET_ID=
MVP_AVATAR_COS_SECRET_KEY=
MVP_AVATAR_COS_BUCKET=your-bucket-1234567890
MVP_AVATAR_COS_REGION=ap-guangzhou
MVP_AVATAR_COS_PREFIX=avatars/
```

先配置完整，再将开关改为 `true` 并重启后端。保持环境文件的受限权限，切勿提交真实凭证，
不要使用 `NEXT_PUBLIC_*` 注入密钥；前端 systemd 无需读取上述配置。
本次开发不会替你填写本地真实凭证，也不会向真实桶上传测试对象。

桶及头像对象必须为**私有读写**。推荐专用子账号密钥，CAM 仅授予指定桶 `avatars/*`
前缀的 `cos:PutObject`、`cos:GetObject`、`cos:DeleteObject`。
SDK 使用 HTTPS 和服务端凭证直接访问，不需要浏览器 COS SDK、CORS、STS、CDN 或自定义域名。
接口始终登录鉴权，不返回 COS URL 或签名。权限管理参考
[腾讯云最小权限指引](https://cloud.tencent.com/document/product/436/31923)，
SDK 参考 [Python 快速入门](https://cloud.tencent.com/document/product/436/12269)。

推荐使用未开启版本控制的专用头像桶。开启版本控制时，成功上传记录会保存并删除对应
VersionId，但响应丢失等情况无法确认版本号；还需要 COS 非当前版本生命周期策略，避免
删除标记后仍保留失败上传的底层版本。不要对整个头像前缀设置按创建时间删除规则，
否则会删除长期使用的当前头像。

## 迁移与请求限制

先备份数据库，再安装锁定依赖并迁移：

```bash
uv sync --locked --all-groups
uv run python -m app.cli upgrade-db
```

新增 Alembic head `b1c2d3e4f5a6`，接续手机号迁移 `a9b8c7d6e5f4`。迁移只新增资源表，
不改写现有用户手机号或预设头像。离线部署需准备 COS SDK、Pillow、multipart 等依赖缓存。

前端同源代理及后端仅为 `/api/v1/profile/avatar/upload` 单独开放请求体 `5308416`
字节（5 MiB + 64 KiB），文件仍限 `5242880` 字节，其他接口仍默认 256 KiB。
如果外部还有 Nginx 等网关，需允许该上传路径至少 6 MiB；不要修改整个 API 的上限。
上传接口为 multipart，不能用 JSON/base64 或客户端指定对象键。

## 故障、清理与备份

上传资源先登记为 pending，再执行处理和 COS 写入；云调用不占用数据库写锁。
保存前重新验证会话、账号、手机号资格和资料版本。失败保留旧头像，成功切换与审计在
同一事务提交。每用户每小时最多 10 次处理尝试，频控记录持久化；最多同时处理 2 个上传。
图片读取使用最多 16 MiB、5 分钟有效的内存缓存，缓存命中也先验证会话及当前引用。
云图片读取最多同时执行 4 个任务，允许有上限的排队，以支持列表同时展示多个头像。

服务启动约 60 秒后检查清理队列，此后每小时检查一次，每次最多 100 条。
未完成上传及旧头像在 24 小时后清理，删除前检查当前用户引用；删除失败保留记录并重试。
关闭模块时不执行云清理；恢复后继续处理数据库中的队列。日志只包含安全错误码和通用失败说明，
不打印 SDK 原始异常、凭证、图片内容和原始文件名。定期关注头像上传 429/503 和清理重试日志。

**现有数据库备份不包含 COS 图片。** 恢复到较旧数据库前，需要同时恢复对应对象备份，
否则数据库可能指向已清理的历史头像。存储桶备份/复制应独立安排。
迁移服务器但继续使用同一桶时，保留数据库并配置有效 COS 凭证即可；凭证可轮换，不参与数据加密。
若更换桶或地域，维护窗口内复制对象，并同步调整资源表中的桶/地域/对象键以及环境配置，
通过读取验证后再清理原桶；仅修改环境中的桶名不会迁移历史头像。

常规回退先关闭模块，保留资源记录。回退 schema 会清除用户的自定义头像引用并删除资源表，
不能自动清理 COS 对象；执行前需导出资源清单供恢复或后续运维清理。

## 人工验收

1. 配置私有桶及环境参数，迁移后重启；已绑定用户可上传，未绑定用户只能使用预设头像。
2. 上传照片，调整裁剪并保存；核对侧栏、个人设置、成员列表和工作记录中的头像。
3. 换头像、切回预设，确认失败时旧头像仍可用，且原图和元数据不在 COS 中。
4. 未登录访问头像接口返回 401，直接访问 COS 对象不能匿名读取。
5. 检查重启后资源与频控仍有效，观察到期旧图清理；确认新头像不被清理。
